## 📂 **Directory Structure Breakdown**

### 1. Hierarchical Outputs (Current System)

**Generated by:** `antibody-test` CLI (post-Nov 16, 2025)
**Structure:**
```
experiments/benchmarks/
└── {model_shortname}/               # e.g., "esm1v"
    └── {classifier_shortname}/      # e.g., "logreg"
        └── {dataset_name}/          # e.g., "VH_only_jain_86_p5e_s2"
            ├── predictions_{model}_{dataset}_{timestamp}.csv
            ├── detailed_results_{model}_{dataset}_{timestamp}.yaml
            └── confusion_matrix_{model}_{dataset}.png
```

**How it works:**
1. `antibody-test` reads model's `_config.json` to extract `model_name` and `classifier` config
2. Calls `get_hierarchical_test_results_dir()` from `directory_utils.py`
3. Creates shortnames: `esm1v_t33_650M_UR90S_1` → `esm1v`, `logistic_regression` → `logreg`
4. Saves all outputs to `{model}/{classifier}/{dataset}/`

**Example:**
```bash
# Command
uv run antibody-test \
  --model experiments/checkpoints/esm1v/logreg/boughter_vh_esm1v_logreg.pkl \
  --data data/test/jain/canonical/VH_only_jain_86_p5e_s2.csv

# Outputs to
experiments/benchmarks/esm1v/logreg/VH_only_jain_86_p5e_s2/
├── predictions_boughter_vh_esm1v_logreg_VH_only_jain_86_p5e_s2_20251116_195704.csv
├── detailed_results_boughter_vh_esm1v_logreg_VH_only_jain_86_p5e_s2_20251116_195704.yaml
└── confusion_matrix_boughter_vh_esm1v_logreg_VH_only_jain_86_p5e_s2.png
```

**Code Reference:** `src/antibody_training_esm/cli/test.py:533-601` (`_compute_output_directory()`)

## 🔄 **How `antibody-test` Decides Output Location**

**Decision Flow:**
```python
# src/antibody_training_esm/cli/test.py:533-601
def _compute_output_directory(model_path, dataset_name):
    if model_path is None:
        return "./experiments/benchmarks"  # Flat fallback

    # Try to load model's _config.json
    config_path = model_path.replace(".pkl", "_config.json")

    if not config_path.exists():
        return "./experiments/benchmarks"  # Flat fallback

    # Parse config for model_name and classifier
    config = load_json(config_path)
    model_name = config["model_name"]  # e.g., "facebook/esm1v_t33_650M_UR90S_1"
    classifier = config["classifier"]  # e.g., {"type": "logistic_regression", ...}

    # Generate hierarchical path
    return get_hierarchical_test_results_dir(
        base_dir="./experiments/benchmarks",
        model_name=model_name,          # → "esm1v"
        classifier_config=classifier,    # → "logreg"
        dataset_name=dataset_name        # → "VH_only_jain_86_p5e_s2"
    )
    # Returns: ./experiments/benchmarks/esm1v/logreg/VH_only_jain_86_p5e_s2/
```

**Fallback Cases (outputs to flat root):**
1. No model path provided
2. Model's `_config.json` not found
3. JSON parse error or missing required fields

## 📖 **For OSS Contributors**

### "I ran `antibody-test` and got weird directories"

**Expected behavior:**
- ✅ Outputs go to `experiments/benchmarks/{model}/{classifier}/{dataset}/`
- ✅ Logs go to `experiments/benchmarks/*.log`

**If you see flat outputs in root:**
- Check if model's `_config.json` exists next to `.pkl` file
- Verify JSON has `model_name` and `classifier` fields
- See fallback cases above

### "What is `novo_parity/` and why is it 75 MB?"

**Answer:**
- Historical research artifact from Nov 3-5, 2025
- Manual reverse-engineering of Novo Nordisk's test set
- NOT generated by `antibody-test` CLI
- Can be safely ignored for normal pipeline usage
- Read `novo_parity/README.md` if interested in methodology

### "Should I commit my test results?"

**Guidelines:**
- ✅ **YES** for validated benchmark results (Jain, Harvey, Shehata)
- ✅ **YES** for published paper replication (Novo parity)
- ❌ **NO** for exploratory experiments or debugging
- ✅ Use `.gitignore` to exclude `experiments/benchmarks/test_*.log`

**Current `.gitignore`:**
```gitignore
# Exclude test logs (gitignored)

# Keep validated results (tracked in Git)
```
